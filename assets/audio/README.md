# Theme audio

The THEME button on the dashboard plays a sound file through the **Pi's own
audio output**, not the browser's. Trigger it from the touchscreen or from a
phone and the cart is what makes the noise.

## What gets played

`config/audio.json` lists candidate files in priority order, and the first one
that exists on disk wins:

```json
"files": [
  "../media/theme.mp3",
  "../media/theme.wav",
  "assets/audio/theme.mp3",
  "assets/audio/theme.wav"
]
```

- **`../media/theme.*`** — a directory *beside* the clone, not inside it. This
  is where your own audio belongs; see below.
- **`theme.mp3`** — nothing ships here. A file dropped in still works and
  takes precedence over the generated fallback.
- **`theme.wav`** — the fallback, generated by `npm run make-theme`. It is an
  original synth piece written for this project, so the repo carries no
  third-party audio.

Neither file under `assets/audio/` is committed (see `.gitignore`): one is a
build artifact, and the other is yours.

## Keeping your audio through a re-clone

Anything inside the clone dies with the clone. Put your file one level up
instead, so deleting and re-cloning the repo cannot touch it:

```
/home/pi/
├── golf-cart-lighting/   ← the clone; safe to blow away and re-clone
└── media/
    └── theme.mp3         ← yours, untouched
```

```bash
mkdir -p ~/media
# from your workstation:
scp your-track.mp3 pi@golfcart.local:/home/pi/media/theme.mp3
```

Relative paths in `files` resolve against the repo root, so `../media/...`
follows the install directory rather than hardcoding `/home/pi`.

This is deliberately **not** solved by committing the audio. Doing that would
publish a copyrighted recording from a public repo, permanently — git history
keeps it even after a later delete. Making the repo private to allow it trades
that for needing a deploy key or token *on the cart*, which is a credential on
a device that lives outdoors in an unlocked vehicle. A file beside the clone
needs neither.

> The Knight Rider theme is a copyrighted 1982 composition and can't be
> redistributed here. If that's what you want the button to play, use a copy
> you're licensed to use and save it as `theme.mp3`.

Any format your player handles works — just point `files` at it. MP3 needs
`mpg123` or `ffplay`; WAV also works with `paplay` or `aplay`.

## Regenerating the default

```bash
npm run make-theme                       # 8 bars, ~16s
node scripts/make-theme.js --bars 16     # longer
node scripts/make-theme.js --out assets/audio/other.wav
```

## Checking audio on the Pi

The service picks a player at startup and logs what it found:

```
journalctl -u golfcart-lighting | grep audio
```

If it reports no player, install one:

```bash
sudo apt-get install -y mpg123 alsa-utils
```

If it reports a player but you hear nothing, the Pi is likely routing audio to
HDMI instead of the headphone jack:

```bash
aplay -l                                 # list output devices
sudo raspi-config                        # System Options > Audio
alsamixer                                # check the level is not zero or muted
```

Test the file outside the controller to isolate the problem:

```bash
mpg123 assets/audio/theme.mp3
aplay assets/audio/theme.wav
```

## Volume

`config/audio.json` sets `volume` (0-100), applied per-player at launch. It
scales against the system mixer rather than replacing it, so `alsamixer` still
has the final say.
